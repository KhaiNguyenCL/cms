  PHASE 3: CLIENT PLAYER - HYBRID ARCHITECTURE
================================================================

KIẾN TRÚC QUYẾT ĐỊNH:
═══════════════════════
Giữ hybrid (Android Shell + Web Player PWA) vì:
- Cập nhật nội dung/logic không cần deploy APK mới
- Web tech đủ mạnh cho video/image/HTML playback
- Android TV system WebView (Android 7+) đã ổn định
- Giảm thời gian phát triển đáng kể

Android Shell (Kotlin - "Smart Shell"):
  ├── KioskManager       ← Boot receiver, navigation bar, screen lock
  ├── SetupActivity      ← Nhập server URL + pairing code (lần đầu)
  ├── PlayerActivity     ← WebView host + native bridge
  │     ├── WebView      → Web Player PWA (toàn bộ content logic)
  │     └── JavascriptInterface → Bridge native ↔ web
  └── HealthReporter     ← CPU/RAM/network metrics native

Web Player (PWA - Vite + TypeScript):
  ├── PlayerEngine       ← Điều phối phát, schedule resolution
  ├── ContentRenderer    ← Video/Image/HTML/URL rendering
  ├── SyncManager        ← API sync + WebSocket
  ├── OfflineManager     ← Service Worker + IndexedDB
  └── CacheManager       ← Cache API strategy

Deployment:
  /api     → Backend API (Node.js)
  /admin   → React Admin Dashboard
  /player  → Web Player PWA ← Android Shell mở URL này

GHI CHÚ VỀ VIDEO PERFORMANCE:
  HTML5 <video> trong WebView đủ tốt cho nội dung signage thông thường.
  Nếu cần hiệu suất cao hơn (4K, decode hardware, DRM):
  → Xem xét thêm ExoPlayer Activity trong Shell (phase sau)
  → JavascriptInterface để Web Player trigger native video playback

3.8  OFFLINE STRATEGY
───────────────────────
*** THIẾT KẾ OFFLINE-FIRST TỪ ĐẦU ***

[ ] SERVICE WORKER (sw.ts)
    Đăng ký khi player load lần đầu
    Chiến lược cache:
    + /player/* (app shell JS/CSS)  → Cache First, update khi version mới
    + /api/device/sync              → Network First + Fallback IndexedDB
    + /media/files/*                → Cache First (đã pre-download)
    + /api/device/heartbeat         → Network Only (không cache)
    + Playback logs offline         → Background Sync (flush khi online)

[ ] INDEXEDDB SCHEMA (idb version 1)
    'device-info'   → { deviceId, token, serverUrl, timezone }
    'schedule'      → { id: 'current', data: SyncPayload, contentHash, savedAt }
    'media-meta'    → { id, checksum, size, cachedAt, expiresAt }
    'pending-logs'  → { id (auto), deviceId, mediaId, playedAt, duration, completed }
    'settings'      → { defaultPlaylistId, maxOfflineDays: 7, contentHash }

[ ] CONTENT PRE-DOWNLOAD
    Sau khi sync: tính diff media mới cần tải
    1. Lấy danh sách mediaId từ schedules active + upcoming 24h
    2. Check mediaId nào chưa có trong Cache API
    3. Tải tuần tự (không parallel để tránh flood bandwidth)
    4. Mỗi file: GET signed URL → download → verify SHA-256 → lưu Cache API
    5. Xóa media không còn trong schedule nào (giải phóng storage)
    6. Progress bar: "Đang tải nội dung: 3/10 (45%)"
    7. Bắt đầu phát TRƯỚC khi tải xong (dùng stream nếu cache miss)

[ ] OFFLINE DETECTION
    Khi offline:
    - Đọc schedule từ IndexedDB
    - Load media từ Cache API (đã pre-download)
    - Tiếp tục phát bình thường
    - Indicator nhỏ ở góc: "● Offline" (màu vàng)
    - Queue playback logs vào IndexedDB pending-logs
    - Nếu offline > 7 ngày: phát fallback screen (logo + thông báo)

    Khi có mạng lại:
    - Sync schedule + download media mới
    - Flush pending-logs qua batch API (max 500/request)
    - Kết nối lại WebSocket

[ ] STORAGE QUOTA MANAGEMENT
    - Kiểm tra navigator.storage.estimate() trước khi download
    - Nếu còn < 500MB: xóa media từ schedule đã qua (oldest first)
    - Ưu tiên: active schedule > upcoming 24h > upcoming 7 ngày > cũ

================================================================
  CÁC NGUYÊN TẮC BẢO MẬT XUYÊN SUỐT
================================================================

1.  NEVER trust client input → validate & sanitize mọi thứ (Zod + DOMPurify)
2.  NEVER store plaintext password → bcrypt cost 12+
3.  NEVER log sensitive data (password, token, PII)
4.  NEVER expose stack trace trong production response
5.  NEVER store refresh token trong localStorage → HttpOnly cookie
6.  ALWAYS dùng HTTPS (TLS 1.2+) cho mọi communication
7.  ALWAYS set Content-Security-Policy headers
8.  ALWAYS rate-limit authentication + device endpoints
9.  ALWAYS kiểm tra permission (org isolation) trước khi trả data
10. ALWAYS validate file type bằng MIME, không phải extension
11. ALWAYS dùng parameterized queries (raw pg $1, $2...)
12. ALWAYS verify checksum SHA-256 sau khi download media
13. ALWAYS dùng signed URL cho media (expire 1 giờ)
14. NEVER cache token/user info trong Service Worker
15. ALWAYS rotate secrets định kỳ (JWT secret, DB password)
16. ALWAYS run npm audit trước khi deploy


================================================================
  KIẾN TRÚC TỔNG QUAN (QUICK REFERENCE)
================================================================

REQUEST PIPELINE (Backend):
  Request
    → Helmet (security headers)
    → CORS (whitelist check)
    → Rate Limit (global 100/15min)
    → Body Parser
    → Route-specific Rate Limit (auth: 5/min, device: custom)
    → authenticateJWT / authenticateDevice
    → authorize(...roles)
    → validate(ZodSchema)
    → Service Layer (business logic)
    → Raw pg (parameterized SQL)
    → Response

DATABASE PATTERN:
  schema.prisma  → dùng để MIGRATE (npx prisma migrate dev)
  raw pg pool    → dùng để QUERY (query(), queryOne(), withTransaction())
  Redis          → JWT blacklist, refresh tokens, pairing codes, rate limit counters

DEVICE LIFECYCLE:
  1. Admin → generate pairing code (6 digits, 5min TTL, Redis)
  2. Android Shell → POST /api/device/register {pairingCode, androidId, ...}
  3. Server → issue device JWT (365 days) + update device record
  4. Player → load, verify token, sync schedule
  5. Player → heartbeat (30s) + playback-log (mỗi item)
  6. Server → push updates qua WebSocket khi content thay đổi
  7. Admin → remote command (restart/screenshot) qua WebSocket → Shell

SYNC FLOW (sau FIX-01):
  heartbeat {currentContentHash}
    → server tính hash mới
    → nếu khác: syncRequired: true
    → device gọi GET /api/device/sync
    → server trả full payload + contentHash mới
    → device cập nhật IndexedDB + download media mới
